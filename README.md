## О проекте

Agro Price Monitor — демонстрационный сервис для фермера. Он позволяет сравнить цены на сельхозпродукцию в четырёх федеральных округах и увидеть разницу между двумя каналами реализации:

- продажа перекупщику;
- продажа прямому покупателю.

Проект расширяет сценарий мониторинга зерновых на более широкий каталог: молочные продукты, мясо, птицеводство и овощи. Данные в демо-версии хранятся в JSON-файле, а рекомендации формируются прозрачными детерминированными правилами.

**Важно:** проект не использует LLM, OpenAI, YandexGPT и внешние AI-API.

## Возможности

- REST API на FastAPI с OpenAPI-документацией;
- список продуктов с фильтрацией по региону, категории, названию и цене;
- получение отдельной записи по идентификатору;
- текстовая рекомендация на основе недельной динамики цены;
- серверный HTML-интерфейс на Jinja2 без React/Vue;
- адаптивный дизайн в стиле РСХБ.цифра;
- CORS для локальной разработки будущего фронтенда;
- Pydantic-валидация входных данных из мок-JSON;
- минимальный набор зависимостей.

### Поток данных

```text
data.json
    ↓
data_service.py  →  Pydantic Product
    ↓
main.py          →  JSON API / Jinja2 HTML
```

Логика фильтрации и рекомендаций находится в `data_service.py`, поэтому API-обработчики остаются короткими, а переход с JSON на SQLite или PostgreSQL можно выполнить изолированно.

## REST API

### Получить список продуктов

```http
GET /api/v1/products
```

Поддерживаемые query-параметры:

| Параметр | Тип | Описание |
| --- | --- | --- |
| `region` | `string` | `ЦФО`, `ЮФО`, `ПФО` или `СФО` |
| `category` | `string` | `Молочное`, `Зерновые`, `Мясо`, `Овощи`, `Птицеводство` |
| `name` | `string` | Поиск по названию продукта |
| `min_price` | `float` | Минимальная цена прямой продажи |
| `max_price` | `float` | Максимальная цена прямой продажи |

Примеры:

```bash
# Все записи
curl "http://localhost:8000/api/v1/products"

# Овощи в Южном федеральном округе
curl "http://localhost:8000/api/v1/products?region=ЮФО&category=Овощи"

# Поиск молока в заданном диапазоне цены
curl "http://localhost:8000/api/v1/products?name=молоко&min_price=30&max_price=40"
```

### Получить продукт

```http
GET /api/v1/products/{id}
```

```bash
curl "http://localhost:8000/api/v1/products/1"
```

Пример ответа:

```json
{
  "id": 1,
  "name": "Молоко",
  "category": "Молочное",
  "region": "ЦФО",
  "price_buyer": 28.0,
  "price_direct": 34.0,
  "change_week": 3.5,
  "updated_at": "2026-10-27T09:00:00"
}
```

### Получить рекомендацию

```http
GET /api/v1/advice/{id}
```

```bash
curl "http://localhost:8000/api/v1/advice/2"
```

Пример ответа:

```json
{
  "product_id": 2,
  "recommendation": "Цена растёт, возможно, стоит подождать.",
  "change_week": 6.8
}
```

### Коды ответов

- `200 OK` — запрос выполнен успешно;
- `400 Bad Request` — некорректный диапазон цен;
- `404 Not Found` — продукт с указанным идентификатором не найден;
- `422 Unprocessable Entity` — ошибка валидации query-параметров.

## Бизнес-правила рекомендаций

Рекомендация считается на основе `change_week`:

| Условие | Рекомендация |
| --- | --- |
| `change_week > 5` | Цена растёт, возможно, стоит подождать. |
| `change_week < -5` | Цена падает, рассмотрите альтернативные каналы. |
| Остальные значения | Стабильная цена. |

Такой подход легко объяснить пользователю, протестировать и заменить на более развитую rule-based модель в дальнейшем.

## Почему это релевантно РСХБ

Проект логично дополняет мониторинг цен на зерно на платформе «Своё Фермерство»:

1. **Расширяет охват.** Помимо зерна показывает молочную продукцию, мясо, птицеводство и овощи.
2. **Сравнивает каналы продаж.** Фермер видит разницу между предложением перекупщика и прямой реализацией.
3. **Готов к интеграции.** REST API можно подключить к мобильному приложению, личному кабинету или отдельному фронтенду.
4. **Повышает прозрачность решения.** Рекомендации работают на понятных бизнес-правилах, а не на непрозрачном внешнем сервисе.
5. **Показывает инженерные навыки.** FastAPI, Pydantic, OpenAPI, CORS, разделение слоёв и серверный рендеринг.

## Ограничения и развитие

Текущая версия — демонстрационный прототип:

- данные статичны и находятся в `data.json`;
- нет авторизации и персональных настроек фермера;
- нет истории цен и графиков динамики;
- цены не являются официальной статистикой;
- CORS разрешён только для localhost-сценариев.

Для production-версии можно добавить:

- PostgreSQL/SQLite и миграции;
- интеграцию с API Росстата и/или официальными данными «Своё Фермерство»;
- регулярное обновление и валидацию источников;
- историю цен, графики и агрегирование по регионам;
- авторизацию, избранные продукты и уведомления;
- пагинацию, сортировку и кэширование;
- Docker, CI/CD, логирование и мониторинг.
